Sequelize es un ORM para Node.js. Permite representar tablas como modelos y realizar operaciones de base de datos mediante métodos de JavaScript.

SELECT * FROM usuarios;

RecuerdaSequelize no sustituye los conceptos de SQL. Los expresa desde JavaScript y genera las consultas correspondientes.

const { Sequelize } = require('sequelize');

const sequelize = new Sequelize(
  'nombre_base_datos',

  'contraseña',
  {

    dialect: 'mysql'
  }
);

¿Qué es una migración?

Una migración es un archivo que describe un cambio que queremos realizar en la estructura de la base de datos y también cómo deshacerlo.

Forma sencilla de pensarlo Una migración es como guardar en un archivo un ALTER TABLE, un CREATE TABLE u otro cambio de estructura para poder aplicarlo de manera controlada.
Antes
usuarios
-------------------------
id
nombre
correo
Queremos llegar a
usuarios
-------------------------
id
nombre
correo
telefono

Ejemplo: agregar la columna telefono

En SQL probablemente haríamos algo parecido a esto:

SQL
ALTER TABLE usuarios
ADD telefono VARCHAR(20);

Con una migración, ese mismo cambio queda registrado en un archivo. Si se utiliza Sequelize CLI, primero puede generarse una migración:

Terminal
npx sequelize-cli migration:generate --name agregar-telefono-a-usuarios

Se generará un archivo de migración. Dentro podemos definir el cambio:

Migration · agregar-telefono-a-usuarios.js
'use strict';

module.exports = {
  async up(queryInterface, Sequelize) {

    await queryInterface.addColumn(
      'usuarios',
      'telefono',
      {
        type: Sequelize.STRING(20),
        allowNull: true
      }
    );

  },

  async down(queryInterface, Sequelize) {

    await queryInterface.removeColumn(
      'usuarios',
      'telefono'
    );

  }
};
up() Indica qué debe ocurrir al aplicar la migración. En este caso: agregar la columna telefono.
down() Indica cómo deshacer el cambio. En este caso: eliminar la columna telefono.

Aplicar la migración

Terminal
npx sequelize-cli db:migrate

Después de ejecutarla, la tabla quedaría conceptualmente así:

Resultado
usuarios
-------------------------
id
nombre
correo
telefono   ← nueva columna

Deshacer la última migración

Terminal
npx sequelize-cli db:migrate:undo

Sequelize ejecutará el método down(). En nuestro ejemplo, eliminará nuevamente la columna telefono.

Importante: migración y modelo no son lo mismo La migración modifica físicamente la estructura de la base de datos. El modelo describe cómo Sequelize trabajará con esa tabla desde la aplicación. Si agregamos telefono a la base de datos y queremos utilizarlo desde el modelo, también debemos agregar ese atributo al modelo correspondiente.
Modelo actualizado
telefono: {
  type: DataTypes.STRING(20),
  allowNull: true
}
Resumen de migraciones
Necesito... En la migración
Crear una tabla queryInterface.createTable()
Agregar una columna queryInterface.addColumn()
Eliminar una columna queryInterface.removeColumn()
Cambiar una columna queryInterface.changeColumn()
Eliminar una tabla queryInterface.dropTable()

¿Y los seeders?

Los seeders no cambian la estructura. Sirven para insertar datos iniciales o de prueba.

Migración
Agrega la tabla roles

Diferencia rápida Migración = modifica la estructura.
Seeder = agrega datos.
Modelo
const Usuario = sequelize.define(
  'Usuario',
  {
    nombre: DataTypes.STRING
  },
  {
    paranoid: true
  }
);

Con paranoid: true, Sequelize usa normalmente una columna como deletedAt para indicar cuándo se eliminó lógicamente el registro.

No es un DELETE físicoEl registro sigue existiendo en la base de datos; simplemente queda marcado como eliminado.
Sequelize + SQL
const resultados = await sequelize.query(
  'SELECT * FROM productos WHERE precio > :precio',
  {
    replacements: {
      precio: 100
    }
  }
);
Cuándo puede ayudarReportes, consultas complejas, funciones específicas del motor o situaciones donde SQL sea más claro que la abstracción del ORM.
SeguridadPrefiere parámetros como :precio y evita concatenar directamente valores proporcionados por el usuario.

Supongamos que queremos una aplicación muy sencilla donde un usuario puede tener varios pedidos.

Objetivo del ejemplo Crear un usuario, registrar un pedido y después consultar al usuario junto con sus pedidos.
Flujo general
1. Conexión 2. Modelos 3. Relación 4. INSERT 5. SELECT + WHERE 6. JOIN con include

1. Conectarnos a la base de datos

database.js
const { Sequelize, DataTypes } = require('sequelize');

const sequelize = new Sequelize(
  'tienda',
  'root',
  'contraseña',
  {
    host: 'localhost',

2. Definir los modelos

Usuario y Pedido
const Usuario = sequelize.define('Usuario', {
  nombre: {
    type: DataTypes.STRING,
    allowNull: false
  },
  activo: {
    type: DataTypes.BOOLEAN,
    defaultValue: true
  }
});

const Pedido = sequelize.define('Pedido', {
  total: {
    type: DataTypes.DECIMAL(10, 2),

4. Crear datos

INSERT con Sequelize
const usuario = await Usuario.create({
  nombre: 'Ana'
});

await Pedido.create({

Equivale conceptualmente a
INSERT INTO usuarios(nombre, activo)
VALUES ('Ana', true);

INSERT INTO pedidos(total, UsuarioId)
VALUES (250.50, 1);
¿Qué ocurrió? Primero creamos al usuario. Después usamos su id como Foreign Key del pedido.

5. Consultar al usuario y sus pedidos

WHERE + include
const resultado = await Usuario.findOne({
  where: {
    nombre: 'Ana',
    activo: true
  },
  include: Pedido
});

console.log(resultado);

En SQL podemos imaginar algo similar a:

SQL conceptual
SELECT *
FROM usuarios
LEFT JOIN pedidos
  ON usuarios.id = pedidos.UsuarioId
WHERE usuarios.nombre = 'Ana'
  AND usuarios.activo = true;

¿Y las migraciones? Las migraciones normalmente se ejecutan antes para crear o modificar físicamente las tablas. El código anterior representa la parte que la aplicación utiliza después para trabajar con esos datos.
